# AGENTS Memory

## Project Goal
- Build a video crowd counting model based on official `mamba-ssm` and `causal-conv1d`.
- The current experimental stage uses ShanghaiTech pseudo-video clips generated by repeating a single frame.
- Experiments in this folder are run on autodl; do not run training locally.
- Bus training commands should use dataset path `/root/autodl-tmp/bus`.

## Current Architecture
- Core model: `VideoMambaCounter`
- Spatial module: `SS2D`
- Spatio-temporal module: `ST_MambaBlock`
- Temporal branch is now bi-directional:
  - depthwise temporal `Conv1d`
  - `temporal_mamba_forward`
  - `temporal_mamba_backward`
  - concat fusion followed by linear projection
- Primary count prediction comes from density integration:
  - `frame_count = density_map.sum(dim=(2, 3, 4))`
  - `clip_count = frame_count.mean(dim=1)`
- Independent `count_head` is kept only as an auxiliary branch:
  - `aux_frame_count`
  - `aux_clip_count`
- The backbone is now a 3-stage spatial pyramid:
  - stem at roughly `1/2` resolution
  - `downsample1` to `1/4`
  - `downsample2` to `1/8`
  - FPN-style top-down fusion before `density_head`
- The codebase now supports:
  - `--dataset shanghaitech|fdst|mall|ucsd|bus`
  - `FDSTVideoDataset` with real sequential frame clips and per-frame point annotations
  - `MallVideoDataset` with single-camera real video clips from `mall_gt.mat`
  - `BusVideoDataset` with fixed-camera real video clips, `amb_gt` density labels, `bus_roi.npy`, and a train-density-derived perspective prior
  - `stem_norm = batch|group|layer|none`
  - `density_norm = batch|group|layer|none`
  - sliding-window evaluation to better align SS2D sequence lengths between train and test
  - adaptive Gaussian density labels and more standard ShanghaiTech preprocessing
  - optional density cache loading from precomputed `.npy` files
  - training speed knobs such as AMP dtype selection, TF32, persistent workers, prefetch factor, sparse validation, and gradient accumulation
